# Markdown Converter for Google Document AI

This module provides functionality to convert Google Document AI JSON output to Markdown format.

## Overview

The markdown converter processes JSON files generated by Google Document AI and converts them to readable markdown format, preserving the structure and layout of the original document.

## Features

- Support for converting both small and large JSON files
- Support for multiple JSON formats:
  - Standard Document AI format with `document_data` and `pages`
  - Alternative format with `files` array and page markers in text
  - Chunked format where document content is split across chunks
  - Hybrid format combining chunk markers with detailed content in `document_data`
- Multiple processing strategies for different file sizes:
  - Direct processing for small files
  - Memory-efficient chunked processing for large files
  - Streaming processing with ijson for optimal performance (when available)
- Automatic format detection and appropriate parser selection
- Automatic fallback mechanism to ensure processing works in all environments
- Preservation of document structure and formatting
- Conversion of academic documents with proper formatting

## Components

- `academic_doc_parser.py` - Main parser that converts standard JSON format to markdown
- `streaming_academic_doc_parser.py` - Streaming parser for large files (requires `ijson`)
- `markdown_handler.py` - High-level handler that manages conversion process and supports multiple formats

## Usage

### Basic Usage

```python
from utils.markdown_converter.markdown_handler import MarkdownHandler

# Convert JSON data to markdown (automatically detects format)
json_data = {...}  # Your JSON data
markdown = MarkdownHandler.convert_to_markdown(json_data)

# Convert a JSON file to markdown
MarkdownHandler.save_file_as_markdown(
    json_file_path="path/to/file.json",
    output_file_path="path/to/output.md"
)
```

### Processing Large Files

The converter automatically selects the appropriate processing method based on file size, format, and available dependencies:

```python
# Process files of any size and format
# Will use:
# - Regular processing for small files
# - Chunked processing for large files
# - Streaming processing for large files if ijson is installed
MarkdownHandler.save_file_as_markdown(
    json_file_path="path/to/large_file.json",
    output_file_path="path/to/output.md"
)

# Explicitly use large file processing
markdown = MarkdownHandler.convert_large_json_to_markdown("path/to/large_file.json")
```

## Supported JSON Formats

The converter supports four different JSON structures:

### 1. Standard Document AI Format

```json
{
  "document_data": {
    "pages": [
      {
        "page_number": 1,
        "lines": [
          {
            "text": "...",
            "layout": { ... }
          },
          ...
        ]
      },
      ...
    ]
  }
}
```

### 2. Alternative Format with Files Array

```json
{
  "text": "...",
  "metadata": { ... },
  "files": [
    {
      "text": "...",
      "metadata": {
        "filename": "document.pdf",
        "page_count": 140
      }
    },
    ...
  ]
}
```

### 3. Chunked Format with Page Markers

```json
{
  "text": "--- Document 1: document.pdf (140 pages) ---\n\n--- Chunk 1 (Pages 1-15) ---\n\n----- Page 1 -----\n\nContent for page 1\n\n----- Page 2 -----\n\nContent for page 2\n\n...",
  "metadata": { ... },
  "files": [
    {
      "text": "--- Chunk 1 (Pages 1-15) ---\n\n----- Page 1 -----\n\nContent for page 1\n\n...",
      "metadata": {
        "filename": "document.pdf",
        "page_count": 140
      }
    }
  ]
}
```

### 4. Hybrid Format (Chunk Markers + document_data)

```json
{
  "text": "--- Document 1: document.pdf (140 pages) ---\n\n--- Chunk 1 (Pages 1-15) ---\n\n----- Page 1 -----\n\n----- Page 2 -----\n\n...",
  "metadata": { ... },
  "files": [
    {
      "text": "--- Chunk 1 (Pages 1-15) ---\n\n----- Page 1 -----\n\n----- Page 2 -----\n\n...",
      "metadata": {
        "filename": "document.pdf",
        "page_count": 140
      },
      "document_data": {
        "pages": [
          {
            "page_number": 1,
            "blocks": [
              {
                "text": "Actual detailed content for page 1"
              },
              ...
            ]
          },
          ...
        ]
      }
    }
  ]
}
```

## Dependencies

- Required: `json`, `re`, `os`, `logging`
- Optional: `ijson` (for optimal performance with large files)

To install the optional dependency:

```bash
pip install ijson
```

## Performance

The converter uses different strategies based on file size and format:

1. **Small Files (< 5MB)**: Loaded entirely into memory for direct processing
2. **Large Files (≥ 5MB) without ijson**: Processed in chunks (10 pages at a time)
3. **Large Files (≥ 5MB) with ijson**: Processed using streaming parser for optimal performance
4. **Chunked Format Files**: Processed with special handling to reconstruct documents from chunks
5. **Hybrid Format Files**: Extracts detailed content from document_data while preserving chunk structure

## Handling Hybrid Documents

The converter now detects hybrid format documents that contain both:
1. Page/chunk markers in the `text` field for structure
2. Detailed content in the `document_data.pages` structure

For these documents, the converter:
1. Identifies the hybrid format automatically
2. Builds a mapping of page numbers to their detailed content
3. Preserves the hierarchical structure (Document > Chunk > Page)
4. Integrates detailed content from `document_data` into the appropriate page sections
5. Processes Greek, Latin, and other non-English content correctly

This ensures that large documents are converted with all available content properly included and organized.

## Troubleshooting

- For optimal performance with large files, install `ijson` with: `pip install ijson`
- If encountering memory issues even with chunked processing, try reducing the chunk size (`CHUNK_SIZE` in `markdown_handler.py`)
- If the markdown output is empty, check the JSON structure to ensure it matches the expected format
- For detailed logging, ensure the logging level is set to `INFO` or `DEBUG`
