# `/adjudicate` — eliminate, then route (escalate only the residual)

Most forks an agent hands to the owner are **forced moves**: what the
repository must do determines the mechanism, and the registers already
encode that. Escalating them is not deference — it spends the one
irreplaceable resource, and it quietly asserts that owner preference
outranks standards the owner ratified.

This skill owns one falsifiable invariant: **no fork reaches the owner as a
menu of open alternatives until every alternative but the residual has been
shown dead against priors.** Offering a multi-choice question when the
registers already kill all but one branch is unfinished work dressed as
consultation.

It is a router with a mandatory elimination walk, not a worksheet — the
worksheets are the deep skills. Duplicating them here would make a filled
form the goal instead of a sound branch choice.

**Portability.** The four gates, their order, and
**elimination-before-escalation** carry to every seeded repo. Bindings
below are **this seed's** placeholders — a member rebinds the gate table
to its own promise register, single-owner principle, negative register, and
reduction doctrine. Cite owners; never restate their substance.

**Not this skill.** A filled elimination table does **not** clear plan or
sign-off gates — those stay with [`/adversarial`](../adversarial/SKILL.md).

## The four gates — in this order, first to speak kills

| # | Role | Bound here to | Kills the branch that… |
|---|---|---|---|
| 1 | **Promise** | [`docs/PURPOSE.md`](../../../docs/PURPOSE.md); CLAUDE.md settled stances; [`docs/DECISIONS.md`](../../../docs/DECISIONS.md) | …weakens what the repository is for, re-opens what was already ruled, or does another repository's job |
| 2 | **Topology** | [`docs/ROT.md`](../../../docs/ROT.md) (one owner per invariant); [`/cut`](../cut/SKILL.md); capability-port form | …puts the invariant anywhere but its single owner, dual-homes a writer, or leaves the failure representable |
| 3 | **Falsify** | [`docs/ROT.md`](../../../docs/ROT.md) named classes; a measurement that already exists | …instantiates a named failure mode — eliminated, not scored |
| 4 | **Reduce** | [`/cut`](../cut/SKILL.md) subtractive proof; [`docs/ROT.md`](../../../docs/ROT.md) § The parsimony contract | …survives while removing less than a sibling that also survives; complication-by-folding is not reduction |

**The order is the content.** Promise first, or reduction deletes the product.
Falsify before you reach for a clever new helper, or the helper gets built
and *then* recognised. Reduce last, or deletion becomes an aesthetic rather
than a consequence.

Do not weigh the gates against each other. Walk them per branch; the first
gate that speaks on a branch kills that branch. Weighing is where preference
re-enters through the back door.

Quantify the falsify gate — a kill asserted without the specimen's numbers
(where numbers exist) is a preference wearing a gate's name.

## Mandatory procedure — elimination before any question

Run this walk **before** any of: a multi-choice question to the owner,
"needs James", "design choice", "your call", a `/cut` / `/plan` /
campaign that treats two mechanism branches as equally open, or pausing
because a measurement contradicted the plan.

A measurement that contradicts a plan is **gate-3 evidence**. It makes
the walk easier, not a reason to stop and ask.

### 1. Name the fork and enumerate the branches

State the decision in one sentence (what must be true after it). List every
seriously competing branch — usually two or three. Do not invent padding
options to look thorough. Do not skip a branch you privately prefer to bury.

### 2. Score each branch (pros / cons against priors, not vibes)

For **each** branch, write a short entry:

- **Pros** — which promise, proper-function necessity, or ratified row it
  serves (cite the path / section / ruling date).
- **Cons** — which gate, if any, kills it, or which necessity it fails
  (cite the same way). "Feels cleaner" is not a pro. "The owner might prefer"
  is not a con.
- **Verdict** — exactly one of:
  - `PRE-SPECIFIED` — a ruling or settled stance already chose this or
    ruled it out (gate 1; cite it).
  - `FORCED-OUT` — topology, a named failure mode, or reduction makes the
    branch inadmissible (gates 2–4; cite which).
  - `FORCED-IN` — the sole branch that survives; necessity or a ratified
    row entails it.
  - `RESIDUAL` — every gate silent on this branch *and* on at least one
    sibling; priors do not decide between them.

A branch cannot be `RESIDUAL` because the agent has not looked. Silence
must be demonstrated by citation attempt (what was checked, what was
absent).

### 3. Collapse

| Survivors after the walk | What you do |
|---|---|
| **Exactly one** `FORCED-IN` (all others `PRE-SPECIFIED` or `FORCED-OUT`) | **Decide.** Record the derivation. Route to the deep skill. **Do not ask the owner.** Presenting the dead branches as a menu is a reject. |
| **Zero** | The fork was misframed, or two registers conflict. Reframe and re-walk, or escalate as *conflict / empty remainder* — never as a preference menu. |
| **Two or more** `RESIDUAL` | Escalation is allowed — **only** the residuals, only after the elimination table shows why every other branch died, and only if the residual falls in "Where this does NOT reach" below. |

The owner is never asked to re-kill a branch the registers already killed.
If you can eliminate all but one, the answer was never a question.

### 4. Escalation shape (when the residual is real)

A valid escalation is not "A or B or C?". It is:

1. The one-sentence fork.
2. The elimination table (every branch, verdict, citation).
3. The residual set (two or more), each still live, with gates shown silent.
4. Which owner-only class it falls in (below).
5. The narrow question over the residual only.

Anything wider is unfinished adjudication.

### Surfacing a fork is not a bypass

A `/plan` sheet, a campaign node, or a cold-read disposition that **names** a
tension has done the first job — never silently wiring an edge or aligning
a doc without saying the conflict. That obligation is **not** permission
to stop there and hand the owner a preference menu.

1. **Surface** the tension in the record.
2. **Run this skill** on the fork (elimination table, verdicts, citations).
3. **If one survivor** — record the derivation and **do not** list it as
   owed to the owner.
4. **If true residuals** — only those go to the owner, in escalation shape.

### 5. Record the derivation

Whether you decided or escalated, write the derivation where the decision
lands — Cut Plan, `/plan` sheet, `campaigns/graph.yaml` node, disposition.
A recorded derivation means the fork does not return next session as an
open menu.

### 6. Evidence-gated forks are registered, not parked

A fork the walk cannot yet collapse for want of evidence is not escalated
and not left in prose: the evidence prerequisites — what fact would kill
which branch — are registered on the owning campaign or sequence entry.
"Deferred" without that trigger is queue-in-chat.

## Then route — the deep skill owns the work

| Fork is about | Goes to |
|---|---|
| engine ownership / topology / a structural cut | [`/cut`](../cut/SKILL.md) |
| salvage-impossible knot | [`/reckless-cut`](../reckless-cut/SKILL.md) |
| a named plan worksheet | [`/plan`](../plan/SKILL.md) |
| ownership of the concern unproven | [`/cold-reading`](../cold-reading/SKILL.md) first |
| governing-document topology | [`/doc-cold-reading`](../doc-cold-reading/SKILL.md) |
| a name | [`/baptise`](../baptise/SKILL.md) |
| is this sustained work, and whose | [`/campaign`](../campaign/SKILL.md) |
| a claim about to be trusted | [`/adversarial`](../adversarial/SKILL.md) |
| a landed finding | [`/verify`](../verify/SKILL.md) then [`/close`](../close/SKILL.md) / [`/log`](../log/SKILL.md) |

Adjudication decides *which branch*; `/cut` decides *how it is built and
proved*. If this skill ever starts holding the how, it has become the
ceremony it exists to prevent.

## Where this does NOT reach

The gates are strong on **ownership and topology** and weak elsewhere.
These stay with the owner — but only **after** the walk shows they are true
residuals, not because the topic "sounds design-y":

- **Product taste** — how a human face feels once the promise is already
  satisfied either way.
- **Performance budgets** — how long a generate or a fetch may run. Not
  whether the promise may be dropped.
- **Promise against promise** — two same-layer promises with no ranking.
- **Amending ratified ground** — reversing a settled stance, widening
  PURPOSE's nine-year-old paragraph to fit the work.
- **Records authoring** — work reports, campaign chronicles.

The line that predicts the rest: **a promise is his, a mechanism is yours.**

## Reject list

- A multi-choice menu on a mechanism question when the walk would leave one
  survivor — the reflex this exists to catch.
- A menu of options with a "recommendation" attached — the same reflex.
- Pausing to report to the owner because a measurement contradicted the plan,
  with the branches the measurement just killed still unwalked.
- Escalating without an elimination table, or with branches unmarked.
- Marking a branch `RESIDUAL` without showing the citation attempt that
  found silence.
- Asking the owner to choose among branches already tagged
  `PRE-SPECIFIED` or `FORCED-OUT`.
- Weighing the gates instead of ordering them.
- Gates walked without numbers where numbers exist.
- Re-litigating a past ruling because the present agent would have chosen
  differently (gate 1 is binding).
- Using an owner-only class name as a skip to avoid the walk.
- Carrying a fork into a handover or `NOW.md` unwalked.
- Shipping a 59-line stub (gate table + invariant, no walk). That is the
  known truncation. The executable half is this file.
- Treating this skill as scoped to mappings or decode tokens because a
  sibling's examples were those — the four gates run on any mechanism
  fork; only the citations change.
- A filled walk with an unsound structure behind it — the table is
  evidence of the reasoning, never a substitute for it.
- Importing Topan's UFI yaml, another member's FR ids, or a member's
  domain examples as if they governed the seed.

## Portability

The four roles, their order, and **elimination-before-escalation** carry
to any project; the bindings in the gate table do not. This is the
universal-core copy (2026-09-12). Origin: Topan `/adjudicate` v2.1.
Procedure: eulogikon's full walk + eukrinikon's 2026-09-10 patches
(numbers on falsify, evidence-gated as queue, handover reject) + piv's
cite-don't-restate discipline.

To rebind in a member: supply a **promise register**, a **single-owner
principle**, a **negative register** of named anti-patterns, and a
**reduction doctrine**. Without a promise register and a negative
register the matrix collapses into vibes. Do not truncate this file to
the gate table.
