# Cold-reading assessment

Layout for the assessment (file it in the work report or the campaign
directory; never chat-only).

```markdown
## Cold reading — YYYY-MM-DD

### What this repo is (evidence-backed)
- (two or three lines, each traceable to a probe output)

### Where the load-bearing code is
- (paths + one line each on why they carry weight)

### What is asserted but unproven
- (claims found in docs/README/chat that no probe confirmed — each is a
  finding, not an insult)

### What is rotting
- (rot classes observed, named against docs/ROT.md)

### Entry decision
- local | structural | campaign — and why
```

Rules:

- Every line in the first three sections cites a probe (#n) or a path.
- "Unproven" is never empty — write "none found" only after naming what
  was checked.
- The assessment expires: re-read before structural work if the last one
  predates the last structural change.
